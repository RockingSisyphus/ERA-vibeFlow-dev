# Service 领域基础库

本目录提供历史规划、状态计算、消息处理与合同转换等领域实现。资源及支撑源码由`../plugins/base_lib/`中的SDK声明登记，当前依赖与来源见`../ARCHITECTURE.jsonc`。运行顺序由`../configs/`的Node／Nodeset及连边决定；基础库不承担浏览器监听、任务控制或图外调度。

酒馆IO、队列、回执与资源生命周期位于`../../tavern`。修改时先沿Architecture定位真实调用与实现，遵循本root的AGENTS和开发总览。

普通变量赋值从本楼开始时的变量状态记录旧值，包含前面楼层对子路径的修改。本楼才创建的路径使用本次赋值前的值。删楼回滚按同一份日志恢复变量。

原生`swipe`新候选生成与`regenerate`重新生成都在放行生成前恢复上一楼变量；即使先前候选切换已处理完，也由生成意图明确触发同一回退任务。普通生成、续写和预演保持各自语义，选择已有候选由原同步任务恢复状态。

消息内函数提交复用普通Facade校验与`era_tx`记录构造。函数位置的计划正文沿用当前阶段消息的候选事实，真实宿主来源依据覆盖同楼事实，并以同一第2版消息合同交给校验器。Agent尚未写入宿主的草稿楼层保留阶段已经构造的候选事实，不能被误当作缺少合同字段；这不表示草稿已保存。函数绑定接口仍读取当前位置并在当前位置提交，不进入外部FIFO等待自身。

原生候选切换后的内存恢复由既有Sidecar检查节点完成：回退记录保留原sourceBasis，写入内存时另用本次派发的expectedSourceBasis校验当前候选及版本。旧候选的记录来源不作为恢复操作的当前目标，消息正文与文件保存仍逐项核对原来源。

Sidecar检查期间若已完成原生候选的内存恢复，后续一致性比较使用该次写入返回的working作为预期工作状态，其他聊天身份、绑定和变量事实仍沿用原读取快照。这样不会把本节点自己递增的工作版本误报为外部来源变化，也不会放行其后的实际并发变化。
