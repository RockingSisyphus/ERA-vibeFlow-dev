# ERA 开发总览

ERA把消息中的变量操作变成可恢复的历史。角色卡作者通过标签、表达式和公共API操作数据，酒馆负责聊天与生成，酒馆助手负责脚本及消息iframe。作者用法见[作者指南](../author/README.md)，本章只解释维护边界。

先看架构逻辑、无需先读后台代码时，使用[工作流阅读指南](工作流阅读指南.md)及其中的最新正式图定位链接。

## 模块关系

| 部分                                          | 职责                                                            |
| --------------------------------------------- | --------------------------------------------------------------- |
| `javascript_project/service`                  | 异步业务服务：历史定位、逐块执行、函数调用、候选恢复、API及保存 |
| `javascript_project/macro`                    | 同步宏解析和投影                                                |
| `javascript_project/expression`、`compaction` | 表达式求值与安全操作压缩，作为业务能力被调用                    |
| `javascript_project/tavern` | 原生酒馆辅助流程：准入、回执、通信及资源生命周期 |
| `app/src/ERA变量框架` | 局部脚本单次入口、公共Facade、宏和UI展示端口 |
| `base_lib/data_view` | Macro、Service和公开快照共用的数据转换，登记为era.data_view |
| `packages`                                    | 跨层合同、快照、宏语法、工作台和共享示例资源                    |
| `generated`                                   | AOT构建输出，不手工编辑                                         |

维护时从所选root的vibeflow_project和ARCHITECTURE沿source定位真实代码。接口事实以源码、schema及`app/@types`为准；没有独立手写一套DTO文档。上游参考不是ERA生产实现。

## 一次购买的生命周期

AI输出购买调用前，普通块先依次修改本次内存状态。到调用位置，作者函数获得绑定参数的API，提交扣钱和增加食物；同一引擎应用这些操作，再继续后面的块。记录写在调用下方，done标记控制以后是否重执行。

运行中内存工作状态与已保存Sidecar分开；commit回执确认内存应用，完整任务或保存窗口结束后先保存消息，再保存Sidecar。普通呈现和ready等待对应保存边界。历史改变时撤销旧效果并重算，目标版本不符时不得覆盖用户新内容。函数位置请求不排到等待自身结束的外部FIFO，外部API和消息操作仍共用业务规则。

回滚后切换较晚楼层的 Swipe 时，中间楼层可能没有已应用记录。定向重算从最近的已应用楼层保留变量与函数状态，只撤销重算范围内的效果。此前完全没有已应用楼层时，才从初始状态重算。

多阶段候选有恢复点，可纠错错误撤销整次候选，早前成功阶段保留。纯历史查询不执行作者工具。状态栏和单层模式只管理呈现与身份绑定，不另建变量权威状态。

阶段继续时，从统一派发正文读取同一楼号、Swipe 和 MK 对应的完成阶段；这份正文已合入尚待保存的提交，不依赖保存时会清空的 WorkingState.stage 标记。规划片段、故事片段及待最终提交正文沿用这同一份内容。已经写进完成阶段的作者事务不再作为额外外部提交复制到正文前缀；原消息与完成阶段共同说明已覆盖的记录次数，相同内容的多次真实提交仍逐次保留。普通保存的文件写入及聊天指针提交复用同一 SidecarId 依据，异步等待期间绑定改变时交回原有来源变化处理。

待写正文投影明确接受本次派发的待写结果，不凭文字差异猜测结果归属。本次派发已经准备了正文时，后续 Sidecar 读取继续保留它，不再用旧 WorkingState 覆盖或重复拼接；完成阶段的占位符规范化和作者事务因此沿同一份正文进入保存。消息密钥保存也使用这份已核对的写入计划，避免插楼或删除后把旧楼的文本写入现在占据同一楼号的新消息。

初始化可能要求用户处理绑定冲突或缺失文件，因此提示界面在发送启动初始化请求前挂载并监听；宏与状态栏继续等待启动回执。挂载和卸载仍由原展示资源释放器管理，不以提示重播缓存补偿顺序问题。

内置面板与外置状态栏共享本脚本拥有的一份宿主样式。后挂载的展示原位更新该样式内容，不删除并重建已有节点；不同脚本的样式节点仍按各自所有者隔离，最终卸载清理本实例资源。

技术内容呈现由 Tavern 启用节点统一登记。App 的投影模块管理 MessageFormatter 的显示副本和出站文本，把楼侧报告容器的挂载与释放交给报告呈现模块。整页恢复时，酒馆可能已先画出消息。投影模块用宿主重新排版后生成的内容修正已有正文，在原位置保留前端容器、iframe 和表单。消息保存节点只交付受影响楼号。该接口要求 SillyTavern 1.19.0 或更新版本。

## 构建与定位

当前工具链为 VibeFlow 1.5.6，Workflow ABI v12，JavaScript AOT 清单 v6。Tavern async 的 operation/runtime 为当前命名入口，适用边界见[工作流阅读指南](工作流阅读指南.md)。业务Node声明已移到各自实现旁的 `.node.ts`，BaseLib声明使用 `.base-lib.ts`；独立 Plugin 提供数据类型、规则和支持资源。Config通过definition_id引用业务定义。Service端口收发已迁为普通Node，原生普通分支已承担资源、Service、串行作者、通知终态和计时职责，见[普通图并发](../../kernel/docs/user/graph-concurrency.md)。主入口仍须保持单次runEra和资源属于workflow，不能以旧任务API或图外调度器兜底。

Tavern生命周期与Macro合同/数据视图已完成首轮构建验证。Service三路共享操作子流程及模块整理也已获批准并实施，并通过静态检查、AOT构建与原生探针；新版真实业务验收尚未完成。旧版本成绩已按当前保留规则清理，不用于本轮验收。当前有效检查、待完成验收和bundle版本见[交接说明](交接说明.md)。

使用仓库指定的Node、pnpm及Python环境；app当前采用Node24与pnpm10。安装依赖按锁文件及workspace约定执行，不改成本机另一套依赖。

```bash
python run.py verify-kernel
python run.py validate --config javascript_project/service/configs/era.service.jsonc
python run.py validate --config javascript_project/macro/configs/era.macro.jsonc
python run.py quality-check --path javascript_project/service
python run.py quality-check --path javascript_project/macro
pnpm --dir app verify
pnpm --dir app build
```

AOT构建采用所选root的VibeFlow命令；先读kernel命令规范，生成物由命令刷新。workflow、Config、Nodeset或执行结构变更遵守AGENTS的四类清单和架构审核；文档整理本身不构造虚假的执行结构审核。

联调优先使用现有酒馆页面及宿主公共接口。`pnpm --dir app dev`提供静态资源和监听；本机端口不能冒充接口事实。修改跨宿主/业务层时同时读局部AGENTS，不在UI或宏中复制业务调度。

生产`build`和`release`会先重建本地合同、公开模块、表达式及压缩包，刷新各消费者锁文件和酒馆接线，再生成四份主AOT，最后打包App；`build:workflows`可单独执行前半段。四份主AOT候选全部构建成功后才替换正式生成目录，构建失败会报出日志而不会调用旧执行器。

主AOT构建的子进程输出直接写入各阶段日志，避免完整构建报告先进入内存缓冲区；首次构建会创建生成目录的父目录。`verify:aot`目前按脚本固定核对Macro的Node 24.18.0、TypeScript 7.0.2及esbuild 0.28.1；准备通过该检查的候选时使用相同版本，不手改生成manifest或放宽断言。

运行 `pnpm --dir app release` 构建本地单文件分发物。ERA-Test-Pack 的 `--era-bundle` 直接指向这次构建生成的 `app/artifact/bundle.js`，运行期间保持产物不变。该文件通过验收后可用于酒馆导入。`pnpm --dir app build` 按 App 各入口生成 `app/dist`。构建、业务验收和发布分别记录。


## 测试职责

`ERA.ready()`加入调用时已接收工作的现有回执等待，再核对工作状态已保存；不会因为上次快照仍为ready便跳过刚入队的候选切换或新消息。不发起额外同步，不等待未来请求或生成阶段交接，也不消费生成屏障的失败记录。消息内函数的上下文ready仍只读取当前计算位置，避免等待自身任务。

原生生成入口在事件目录中显式绑定：ERA 逻辑 `generation_started` 来源于酒馆 `GENERATION_AFTER_COMMANDS`，名称按宿主实际大小写并由本仓接口类型约束，进入原有高水位屏障。酒馆更早的 `generation_started` 在斜杠命令处理前发出，命令直接返回时没有实际回复或结束事件，不能据此持有待生成候选。此绑定由既有 Tavern 监听安装节点执行；Service 逻辑事件、公开 API、Base 职责及原生接收事件保持不变。

ERA-Test-Pack提供业务场景、fixture、独立oracle；ST-Test-Harness负责真实动作、隔离、采集和Artifact；ST-Response-Lab提供本地固定模型响应。真实ERA测试统一经Pack，提供本轮实际构建的bundle，不修改业务预期掩盖失败。旧App `test:e2e`仅读取历史summary而不执行测试，已移除；不能用历史摘要代替当前bundle的端到端验收。

执行步骤、批量修复循环、分段续跑、独立验收和心跳要求统一见[回归测试与问题处理](回归测试与问题处理.md)。每次真实测试启动前使用 `long-running-task-monitor`；启动约 10 分钟观察，健康后约 60 分钟检查，临近结束按可靠 ETA 调整。安全活跃的 suite 不因个别业务失败停止测试或失去监控。

当前状态写入[交接说明](交接说明.md)，运行日志及 Artifact 存运行资料目录；任务记录按 skill 管理，任务结束停止监控，不永久增加历史计划/报告目录。未经用户明确授权不打开 human-review，不推送 Git 或进行发布。


### 测试结果保存

新测试只写一份原始结果，审计直接读取它，不创建整批镜像。审计后使用 ERA Pack 的 `finalize --artifact <原目录> --slot integrated|detail|targeted` 收尾，并按用户2026-11-12要求统一维护当前一份结果汇总：各范围及版本单独列明，不收藏过去批次。
成功路径仅留汇总，删除动作、截图、Console、trace和沙箱详情；仍未解决的每条失败仅留一份最新详细证据，验证解决后立即删除。旧批次、重复归档和已解决失败均删除，不以压缩保存历史替代清理。未执行、缺损和未验收范围继续如实列在当前汇总，不能因为删除旧记录就改成通过。活动作业结束并审计后再清理其输出；工具、固定测试定义和当前依赖按实际运行输入管理。

## 开发资料存放

`reports/`仅保留当前检查输出；`generated/`根目录仅保留当前Service、Macro、Tavern AOT及其依赖链接。表达式和压缩root内的`generated/release`是公共包实际入口，继续保留。执行构建和探针会重新生成相应产物，不维护旧版本构建副本。

本项目的任务资料与临时材料只放在当前开发目录内。过时TODO、旧审核、历史验收附件和旧构建直接删除，不迁到外部归档目录。当前结论和限制统一记录在交接说明；需要进一步验证时重新使用现行源码与测试入口。共享测试工具链的既有服务数据不因本项目清理而搬移或删除。

## 安装入口

App使用`app/pnpm-workspace.yaml`及`app/pnpm-lock.yaml`；各JavaScript root按各自package-lock安装。旧根级pnpm workspace、锁文件及其node_modules已退役，不能在仓库根目录执行安装来代替App安装。共享包构建脚本显式使用App或所属root的工具链。架构和预览由当前内核命令生成。

本机测试的隔离目录和运行句柄由[开发交接](交接说明.md)指向当前任务记录。执行和结果留存规则见[回归测试与问题处理](回归测试与问题处理.md)。

独立BaseLib需由每个workflow的 `base_lib.modules` 显式选择，包含实际使用的传递依赖；Node的 `base_libs` 和库的 `dependencies` 只描述依赖关系，不自动授予使用权限。Plugin贡献的库只随Plugin整包选择。

Service内存行为测试通过`pnpm --dir app build:test-workflows`从正式Nodeset生成测试入口，`test:unit`自动执行此准备步骤。源码、声明、依赖包或工具链变化时重新构建，未变化时复用编译产物；每次仍运行业务断言。缓存标记属于测试构建器，保存在AOT目录外，避免影响VibeFlow正常替换产物。测试适配器只准备完整输入和读取结果，不保留旧操作调度器。CRUD和快照的迁移前行为期待是静态数据，不在运行测试时重新生成。
