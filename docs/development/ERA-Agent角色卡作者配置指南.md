# ERA Agent 角色卡作者配置指南

## 1. 什么时候启用

ERA Agent 提供两个独立选项：

- **正文前规划与函数调用**：适合需要先掷骰、检定或确定分支，再写故事的角色卡；
- **正文后独立变量解析**：适合让故事模型专注叙事，再由辅助模型更新 ERA 变量。

两个选项都关闭时就是原有 ERA 行为。群聊不支持 Agent；角色卡作者应让群聊继续走默认生成。

## 2. 在悬浮球中配置

打开 ERA 悬浮球的“多阶段生成”页：

1. 分别开启需要的阶段，并设置失败后的重试次数（0～16）。
2. 为每次尝试选择预设：ERA 内建、当前正在使用，或酒馆已导入的指定预设。
3. 选择模型来源：酒馆当前连接与模型，或 ERA 本机自定义 API。
4. 可添加多条尝试配置；实际重试超出列表时复用最后一条。
5. 保存到当前角色卡。生成已经开始后再修改，只影响下一次生成。

“当前正在使用”会捕获包含尚未另存修改的当前预设；选择已导入预设会读取指定名称。两者都会
转成脱敏快照写入角色卡，之后不会随本机同名预设的修改自动变化。需要更新时请主动重新捕获。

## 3. 自定义 API 方案

每张规划或变量解析尝试卡都可直接配置 Tavern Helper 支持的 OpenAI-compatible API：选择已有
方案，或者在卡片内填写名称、API 地址和密钥后直接加载模型；模型列表不可用时也可手动填写
模型名。保存整页时 ERA 会先创建或更新这些本机方案，再把返回的方案引用写进角色卡。不需要
先去另一个区域建立方案再回来选择。

方案和密钥只存在本机，不随角色卡发布。角色卡保存的是方案引用，因此作者在自己的设备上可
直接使用；其他用户导入后会看到“需要重新绑定”，需要创建自己的连接方案并重新选择。ERA 不会
偷偷改用酒馆当前模型。

密码输入不会复制到其他尝试。空密码表示保留已有密钥；清除密钥、删除方案和另存为都是显式
动作。模型加载失败不会覆盖当前选择。角色卡局部正则是否启用不影响多阶段生成，ERA 已内建报告
折叠和后续提示清理。

## 4. 发布角色卡

PNG、JSON 和 CharX 导出会带上：

- 两个阶段的开关、重试次数和尝试顺序；
- 脱敏后的预设快照及显示名称；
- 模型来源、模型名和不透明的本机方案引用。

不会带上 API 地址、密钥、本机方案库、代理、脚本、正则脚本或无关扩展设置。发布前建议在一份
新导入的角色卡上检查：开关与快照存在、自定义方案显示需要重新绑定、默认关闭路径仍正常。

## 5. 编写函数与提示词

规划阶段只能请求当前 `statFunc` 和 ERA 有限数值内建函数。建议为卡片提供规则无关、名字明确的
函数，例如 `dice(min,max)`、`percentCheck(skill)`，并让规划预设只返回严格 JSON 调用表。

结算预设应只根据正式故事和生成前快照产生 ERA operations，不要自行拼接 `<era_tx>`。正文阶段
仍使用玩家当前故事预设，因此角色卡既有世界书、预填充和思维链策略不需要迁移到辅助预设。

## 6. 失败与重试

- 规划失败：故事请求不会继续，聊天中显示 ERA 规划失败消息；
- 结算失败：故事保留并标记“变量未结算”，不会写入伪造事务；
- 最新消息可在 UI 中重跑规划、故事或变量结算；
- 编辑历史消息只触发 ERA 的确定性事务重放，不会再次请求模型。

更多运行时与消息格式见 [ERA三段式故事编排器初步设计.md](ERA三段式故事编排器初步设计.md)。
