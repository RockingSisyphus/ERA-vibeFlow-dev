# ERA 消息内函数调用作者指南

本文面向**角色卡作者**，说明如何注册函数、如何在消息里写出调用、ERA 如何处理它们，以及哪些行为是明确不支持的。

状态说明：**特性尚未端到端接通真实酒馆**。语法、块步进、宿主调用会话、位置绑定提交与操作区记录均已实现并有测试保护，但工作流步骤边界与 Host 适配层接线仍未完成（见文末「当前实现边界」）。本文按**已确定并已实现的行为**描述，未接通的部分单独标注。

## 1. 注册函数

用酒馆自身的工具注册系统注册，函数名、参数与处理逻辑都由作者提供：

```js
SillyTavern.registerFunctionTool({
  name: 'attack',
  displayName: '攻击',
  description: '对目标造成伤害',
  parameters: { type: 'object', properties: { damage: { type: 'number' } } },
  async action(args) {
    // 在这里读写 ERA 变量
    await ERA.commit([{ edit: { hp: { $expr: `hp - ${args.damage}` } } }]);
    const after = ERA.get();
    return `剩余 HP：${after.statData.hp}`;
  },
});
```

- **同名覆盖**：再次注册同名工具会覆盖前一个（酒馆行为，仅打警告）。
- **函数来源唯一**：ERA 不另建注册表，执行的就是酒馆注册表里的同名工具。
- 酒馆原生工具调用（模型直接发起）不受影响，仍按原有方式工作。

## 2. 在消息里写出调用

在正文中按**出现位置**写出自闭合调用块：

```text
你拔出长剑，欺身而上。
<EraFCall name="attack" args='{"damage":30}' id="c1"/>
藤蔓缠上你的脚踝——
```

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 已注册的工具名。缺失或为空时报 `ERA_FCALL_NAME_REQUIRED`，该调用不执行但仍写标记。 |
| `args` | 否 | JSON **对象**，省略时为 `{}`。不是合法 JSON 对象时报 `ERA_FCALL_ARGS_INVALID`。 |
| `id` | 否 | 消息内锚点，用于把调用与它下方操作区对应起来。同名同参的多处调用**各自独立**，不按名称或参数去重。 |
| `status` / `error` | 否 | 由 ERA 写入，作者不需要手写。 |

**规范写法是首字母大写的 `<EraFCall>`**；解析大小写不敏感（`<erafcall>` 同样能识别），但作者文档与提示词统一用规范写法。

### 位置约束

调用块**只允许与六类变量指令同级出现在顶层**。嵌在其它标签内部时：

- 报 `ERA_FCALL_NESTED` 诊断；
- **不执行**该调用；
- 不阻断后续块。

## 3. 执行顺序：每个操作块各自一步

ERA 把消息里的每个操作块当作**一步**，按原文位置逐块读取、逐块执行、逐块推进：

```text
<VariableInsert>…</VariableInsert>      ← 一步
<VariableEdit>…</VariableEdit>          ← 一步
<EraFCall name="attack" id="c1"/>       ← 一步（到这一步停下，调用函数）
<EraFCallTx for="c1">…</EraFCallTx>     ← 区内操作块随后各自一步
<VariableDelete>…</VariableDelete>      ← 一步
```

**只有这条消息再无新块时才算处理完成**，才走原来的消息收尾（压缩、提交、呈现、发布快照）。

到达无标记调用时 ERA **无条件断开当前批次**：本批次不提交任何状态，只把调用位置（楼层、块下标、调用标识、参数、该位置的累计状态）交给 Host。函数由 Host 在步骤之外执行，产出的操作随后作为新的操作块写进调用块下方的操作区，整条消息再按原文位置一次性重放并提交。这样函数效果既不占用 FIFO，也不会先提交「还没有函数效果的半条消息」。

## 4. 函数里的 ERA API

函数运行在**绑定调用位置**的上下文里：

| 调用 | 行为 |
| --- | --- |
| `await ERA.commit(operations)` | 操作被登记为**本次调用在调用位置的操作**，返回 `{ status: 'applied', sequence }`。这些操作随后写进调用块下方的操作区，整条消息按原文位置重放时生效。 |
| `ERA.get()` | 读取调用位置的累计状态：已提交侧车状态 + 本条消息在调用之前的块。 |
| `ERA.sync` / `ERA.history` / `ERA.statusbar` | **位置绑定上下文不支持**，报 `ERA_POSITION_BOUND_UNSUPPORTED`。 |

**同一函数内不要依赖 `ERA.get()` 读回自己刚提交的写入**：位置状态的推进由 Service 在
整条消息重放时按原文位置完成，宿主不会在函数内再跑一遍变量引擎（复制一套会让两侧
状态分歧）。需要读回时请在函数内自行维护派生值，或把计算拆到调用前后的普通操作块里。

`commit` 的两种拒绝（都不会静默丢弃）：

- `ERA_POSITION_BOUND_UNAVAILABLE`：当前没有位置绑定调用（例如在函数之外提交）；
- `ERA_POSITION_BOUND_CANCELLED`：调用已取消（切聊、停止、页面卸载），此后提交一律拒绝。

**重要**：位置绑定的提交**不进入普通队列**。请不要在函数里依赖「提交会被排队稍后处理」——这是有意设计，若入队，处理该消息的事件会与等待函数返回的自身互等。

## 5. 操作记录与「已处理」

函数产出的操作写成调用块**下方的操作区**：

```text
<EraFCall name="attack" id="c1" status="done"/>
<EraFCallTx for="c1">
<VariableEdit>{"hp":{"$expr":"hp-30"}}</VariableEdit>
</EraFCallTx>
```

- 操作区只作**来源归属**；其中每个操作块与原文操作块同权，按原文位置重放。
- ERA 自己写出的操作区**不带 `applied="1"`**：函数效果的唯一生效路径就是这份记录随消息重放。把 ERA 写出的操作区手工改成 `applied="1"` 会让函数效果凭空消失。
- **已处理判定**：`status="done"` **或**下方紧邻存在操作区，任一成立即跳过函数本体，只重放其操作。
- 成功但没有产生任何操作的调用也会写标记（空操作区），因此不会每次同步都重复执行。

操作区保留作者提交的含义：提交 `$expr` 就保存表达式，提交固定值就保存固定值。

## 6. 失败与取消

| 情况 | 行为 |
| --- | --- |
| 函数抛错 / Promise 拒绝 | 结束本次调用、保留**已成功应用**的操作、写 `status="done"` 与 `error="ERA_FCALL_FAILED"`、继续后面的块。不回滚。 |
| 工具未注册 | 同上，并记录未注册事实供提示作者；`invokeFunctionTool` 失败时**返回 Error 对象而不抛异常**，因此必须显式判错。 |
| 作者自行捕获异常后正常返回 | ERA 继续等待并按成功处理。 |
| 切聊 / 停止 / 页面卸载 | 作废调用上下文；**迟到的返回值不写回**，后续提交被拒绝。 |
| 自动同步 | **不重试**已标记的调用。 |
| 页面刷新导致块游标丢失 | 从该楼楼首按文本重算：已标记调用不重跑，未标记调用**最多重跑一次**。ERA 不承诺跨中断的外部副作用恰好一次。 |

## 7. 只读与纯计算入口

历史查询、状态栏快照、试算与压缩校验**不执行作者函数**，只报「未执行」诊断并继续处理后面的操作块。需要真正执行的无标记调用由正式同步处理。

## 8. 多阶段生成（规划 / 正文 / 结算）

- **规划阶段**：规划草稿支持调用块的位置执行，操作写回规划草稿的操作区，随本轮消息提交。
- **正文阶段**：结算开启时，正文模型写的 `<EraFCall/>` 与 `<EraFCallTx>` **被隔离**（只进审计、不是写入者），不会执行。作者要表达正文内的判定，请在**规划阶段**完成，把结果通过计划注入正文。
- **结算阶段**：结算模型读到的状态已包含此前执行过的操作；提示词已说明故事中的 ERA 标签已被隔离。

## 9. 压缩

含 `<EraFCall` 的楼层**整层跳过封存压缩**，原文保持字节不变。原因：压缩会合并或移位相邻指令块，一旦操作块被移出所属操作区，调用与其产出的操作就会脱钩。

## 10. 明确不支持

- 在函数里调用 `ERA.sync` / `ERA.history` / `ERA.statusbar`；
- 把调用块嵌进其它标签内部；
- 依赖「函数重跑时外部副作用只发生一次」——请自行保证幂等；
- 在正文阶段编写需要执行的调用（结算开启时正文标签不是写入者）。

## 当前实现边界

以下部分**尚未接通**，因此本文描述的端到端行为目前在真实酒馆中还不能完整生效：

1. **服务侧交接与恢复已接通**：无标记调用会无条件断开本批次，交接事实以 `era.message.invoke_required` 后置通知交出；`era.message.invoke_continue` 恢复事件会把调用标记与操作区写进处理楼层文本，再走既有重放与提交链。交接工作项声明为不提交，因此未完成的消息不会推进连续处理状态。
2. **Host 执行驱动与位置门面已接通**：`tavern-adapter` 收到 `era.message.invoke_required` 后在步骤之外驱动函数（登记 → 位置门面下执行 → 收集产出操作 → 回送终态），函数内 `ERA.commit` 走位置通道而**不入队**，`ERA.get()` 读到的是调用位置状态。
3. **块级工作流步骤尚未拆开**：块推进目前仍在一次同步运行内按序走完，尚未体现为 `vibeflow.loop.while` 的逐块步骤；`block_cursor` 已报出，但还没有写入服务状态（需要给 `EraTaskStateUpdateV1` 增加 `syncCursor`，属独立 ABI 变更）。
4. **尚未在真实酒馆端到端验收**：以上接通目前只有单元与集成测试证据；Pack 的函数注册资产与 MSG-FCALL 预期结果（Evaluator/oracle）尚未落地，因此专项测试还不能在真实酒馆里执行。
