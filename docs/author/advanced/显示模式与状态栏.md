# 显示模式与状态栏制作

推荐把冒险者的生命、金币和背包放在外置状态栏，再按需开启单层模式。这样剧情继续推进时，当前状态留在固定位置。希望阅读每楼当时状态的作者，可以选择传统楼内状态栏。

| 特性     | 外置状态栏                   | 传统托管状态栏              |
| -------- | ---------------------------- | --------------------------- |
| 位置     | 聊天与输入框之间             | AI消息内                    |
| 默认读取 | 当前聊天最新状态             | 所在消息处理后的状态        |
| 写入位置 | 当前目标AI消息末尾           | 所在消息及Swipe的末尾       |
| 模板编辑 | 外置区域“编辑”               | 角色卡“ERA 状态栏模板”正则  |
| 运行环境 | 原生HTML及显式提供的公共接口 | 酒馆助手消息iframe及ERA挂载 |

## 推荐路线的显示设置

外置HTML和启用开关随角色卡保存。编辑器自动保存，失焦或关闭编辑器会提交；确认“已保存”后点击“刷新”，才会重新创建iframe并执行新脚本。普通变量变化只更新绑定和订阅，保留表单与节点。失败草稿保留在本页面，关闭页面前应完成保存；外部库链接会分享，库文件不会自动打包。

外置环境提供ERA、TavernHelper及SillyTavern公共入口，不默认加载jQuery、Vue或Tailwind，也没有所属消息楼号。如下片段显示当前金币：

```html
<p>金币：{{ERA:era_demo.rpg.gold}}</p>
<p id="food"></p>
<script>
  (async () => {
    const render = (state) => {
      document.getElementById("food").textContent =
        `食物：${state.statData.era_demo.rpg.food}`;
    };
    render(await ERA.ready());
    ERA.subscribe(render);
  })();
</script>
```

金币从10变为4时宏更新，食物从1变为3时订阅更新。HTML不加Markdown围栏。脚本用API读结构化数据，不把ERA宏写进JavaScript。普通酒馆宏在挂载和显式刷新时求值；ERA文本和非执行属性绑定随状态更新，样式内ERA宏在首个就绪状态求值一次。

“单层模式”另在设置中启用并保存，默认关闭。它仅保留最后一条AI回复的显示；新回复尚未出现时保留上一AI楼。聊天数据、历史计算、外置栏和后台角色脚本不被删除。关闭后恢复酒馆正常历史窗口，不强制展开所有历史。

旧楼iframe卸载会停止其脚本、动画和音频并丢失临时表单；恢复显示会再次运行加载脚本。作者自行向父窗口注册的监听仍应自行注销。单层与外置配置都绑定单角色卡；群聊不提供这套角色配置入口。关闭悬浮球不会关闭已启用的外置栏。

## 传统模板的挂载结构

楼内模板保留以下骨架，确保读取绑定到所在楼，而不是最新聊天：

```html
<!-- html> Tavern Helper 前端片段识别标记 -->
<script data-era-statusbar-bootstrap>
  const mount = () => window.parent.ERA.statusbar.mount(window);
  window.eraStatusbarMounted = window.parent.ERA
    ? mount()
    : waitGlobalInitialized("ERA").then(mount);
</script>
<section data-era-statusbar-root="v1" hidden inert>
  <p>本楼金币：{{ERA:era_demo.rpg.gold}}</p>
</section>
<script>
  (async () => {
    await window.eraStatusbarMounted;
    const state = await ERA.ready();
    console.log("本楼金币", state.statData.era_demo.rpg.gold);
  })();
</script>
```

先挂载，再执行依赖ERA的脚本。挂载后使用本楼ERA，不要再次调用waitGlobalInitialized替换局部接口。旧非托管模板不会被自动升级。无需启用已退役的“强制重载状态栏”；正常更新不会重新执行加载脚本。

宏 `{{ERA:path}}` 输出去除元数据的值，`{{ERA-withmeta:path}}` 保留元数据；例如前者显示背包内容，后者便于作者检查背包保护。缺失值显示为空，复杂值按JSON展示。首次未就绪时应等待ready，而不是写入试探。

## 旧楼按需显示

默认激活最近3个含托管状态栏的AI楼。更早的楼可以用placeholder显示休眠提示、empty保留空壳或hidden隐藏外壳；这些设置与卸载旧消息的单层模式不同。

模板可在根节点声明 `data-era-overflow="empty"` 或 `data-era-force-display="true"`。已有实例可调用 `await ERA.ready({force:true})`；同步get请求强制显示后仍可能先得到loading。UI的“显示本楼状态栏”一次额外展开一楼，“收起本楼状态栏”恢复范围策略。

例如查看购买前的10金币旧楼，展开后读取该楼状态，不会把当前余额4改回10。休眠根保持hidden/inert，ready等待且写入拒绝；已运行作者脚本不因此自动撤销。实例尚存时唤醒保留节点，单层卸载后重新挂载则是新实例。

写按钮和查询历史的方法见[API与交互脚本](API与交互脚本.md)。
