# 变量结构与保护规则

背包、角色和任务需要不同的数据结构。本章说明操作如何作用于这些结构；计算数值的方法见[表达式与函数库](表达式与函数库.md)。

## 操作与数据结构

所有操作块按消息中的位置执行。Insert 只添加不存在的内容；Edit 只修改已存在的目标；Delete 删除指定目标。根对象用来组织路径，不能用删除操作移除整个根。

```xml
<VariableInsert>{"era_demo":{"quests":{"ruins":{"stage":"寻找入口"}}}}</VariableInsert>
<VariableEdit>{"era_demo":{"quests":{"ruins":{"stage":"进入遗迹"}}}}</VariableEdit>
<VariableDelete>{"era_demo":{"quests":{"ruins":{}}}}</VariableDelete>
```

任务依次出现、更新、移除。空对象是删除整个目标的写法；非空对象继续指定更深的删除位置。已有值不会因为重复 Insert 被重置，Edit 也不会代替 Insert 创建新字段。

| 数据                     | 使用规则                                                                       | RPG例子                                                        |
| ------------------------ | ------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 数字、字符串、布尔、null | 用其实际JSON类型；Edit替换已有叶值                                             | 金币10、地点“遗迹”、存活true                                   |
| 对象                     | 按键递归处理；对象Edit不是删除缺失键的整树替换                                 | 修改任务stage不会顺带删掉clues                                 |
| 数组                     | 按整体值更新；其中对象或嵌套数组元素会被规范化为字符串，不作为可嵌套修改的实体 | 简单背包用 `["火把","绳索"]`；有耐久度的装备改用按ID索引的对象 |
| 特殊键                   | JSON安全编码由ERA处理；作者使用公开路径与原始键，勿自行写内部转义值            | 带标点的道具名应优先作为对象的name值，实体ID用简单键           |

模板适合为多个同类NPC补充默认字段。在父对象放入 `$template`，新插入的对象会先取得模板默认值，再由显式内容覆盖：

```xml
<VariableInsert>{"era_demo":{"npcs":{"$template":{"hp":10,"mood":"平静"}}}}</VariableInsert>
<VariableInsert>{"era_demo":{"npcs":{"guide":{"name":"米拉"}}}}</VariableInsert>
```

`guide` 得到 hp、mood 和 name。模板不追溯修改已有NPC；数组按整体替换规则合并。嵌套模板中，继承模板和父节点本地模板合并，本地值优先；明确指定的子项可以覆盖通用子模板。

## 用meta约束AI操作

保护配置写在要保护的对象内部。下面让主角身份可查看但不能被普通Edit改写：

```xml
<VariableInsert>{"era_demo":{"identity":{"name":"阿斯特","$meta":{"updatable":false}}}}</VariableInsert>
```

| 设置                    | 行为                                                           | RPG用途                            |
| ----------------------- | -------------------------------------------------------------- | ---------------------------------- |
| `updatable: false`      | 拒绝对该节点继续进行普通Edit；默认允许                         | 锁住主角身份                       |
| `necessary: "self"`     | 保留节点自身，内部内容仍可删                                   | 保留背包容器，允许移除道具         |
| `necessary: "children"` | 拦截以空对象直接删除直属子节点；节点自身及更深层按各自规则处理 | 保留装备槽位，允许删除槽内临时字段 |
| `necessary: "all"`      | 拦截该节点和后代的普通删除                                     | 保护主线任务及其进度树             |
| `unInsertAble: "self"`  | 阻止新增直属键，允许对已有子对象继续递归插入                   | 固定装备槽位种类                   |
| `unInsertAble: "all"`   | 阻止整棵子树普通插入；meta维护仍有专用通路                     | 禁止AI凭空生成背包道具             |

请使用这些明确值，不将 `necessary: true` 当作上述字符串策略的替代。保护是操作规则，不是任意JavaScript脚本或外部副作用的权限系统。

解锁修改可显式把 `updatable` 改为true；若仍需保护，再在后续块恢复false。解除删除保护可以删除 `$meta.necessary`，然后删除目标；解除插入保护可以删除相应meta字段，再进行Insert。不要依赖某个混合操作块“顺便穿透”所有保护。

```xml
<VariableEdit>{"era_demo":{"identity":{"$meta":{"updatable":true},"name":"阿斯特·晨星"}}}</VariableEdit>
<VariableEdit>{"era_demo":{"identity":{"$meta":{"updatable":false}}}}</VariableEdit>
```

表达式函数也能设置修改和删除保护，但函数是平面实体：不支持 `unInsertAble` 和 `necessary: "children"`。详见[函数库](表达式与函数库.md#维护表达式函数库)。

## 用工作台检查设计

ERA变量工作台支持按名称、路径或值搜索，新增、编辑、删除，选择值/表达式/JSON模式，以及批量提交操作或对照完整状态生成差异。确认保存前查看操作预览。例如把商店价格从3改为4时，预览应只包含价格变化，不应包含背包删除。

受保护目标会提示选择处理方式；界面支持的临时解锁会在修改后恢复保护，永久解除则改变之后的操作规则。批量状态编辑也通过ERA操作提交，不是绕过历史直接替换Sidecar。

“繁体转简体”是可选输入规范化设置，不是翻译器。开启前在新聊天验证你的中文变量键和值；避免同一系统混用繁简不同的路径。
