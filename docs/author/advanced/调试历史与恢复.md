# 调试、历史与恢复

购买后余额不符时，先查产生变化的消息和操作，不要反复初始化卡片。ERA用消息中的操作恢复历史，运行时维护内存状态，并将状态与日志保存到Sidecar；聊天只保留关联指针及可重放内容。

## 从一次错误购买定位问题

1. 在变量工作台搜索gold、food，核对值及保护配置。编辑和批量差异说明见[变量结构](变量结构与保护.md)。
2. 查看操作详情及消息标识；在历史查看器按消息ID或MK查询购买前后状态。历史视图只读，不修改当前余额。
3. 检查函数是否done、是否重复存在操作记录，或AI同时输出了购买函数和手工扣款。函数工作台用于表达式函数，不显示角色脚本注册的所有JavaScript工具。
4. 多阶段问题展开相应阶段报告，核对实际提示、响应和诊断，再选择重新结算等动作。

## 编辑、分支与重算

| 操作             | 预期行为                           | RPG例子                                          |
| ---------------- | ---------------------------------- | ------------------------------------------------ |
| 编辑、删除旧AI楼 | 撤销旧影响，按当前历史重算后续     | 删掉购买剧情，恢复相应余额                       |
| Swipe或重生成    | 恢复当前选择分支的状态             | 走商店分支有食物，放弃购买分支保留金币           |
| Continue         | 保留已有内容，再处理新增部分       | 同一回复继续获得战利品                           |
| 重算最后一楼变量 | 重算最新楼的效果                   | 修改末楼数量后检查结果                           |
| 完全重算变量     | 依据整段历史重新计算               | 多处历史编辑后恢复一致状态                       |
| 回滚到消息ID     | 变量回到该楼处理后的状态，不删正文 | 检查进入遗迹前的背包；后续正常同步仍依据现存历史 |

用户消息中的变量指令不作为AI操作执行。仅查询history、预览、状态栏快照或压缩校验不会执行作者函数；实际同步遇到无done调用仍会执行。带done的调用重放其普通记录，不重做外部动作。

## Sidecar、跨卡与恢复

导入聊天或切换角色版本后，若同一个Sidecar身份指向另一所有者，ERA会要求选择迁移原变量、创建独立变量或复制原变量。迁移/复制通过可重放操作写入当前聊天；例如将老版本勇者的背包复制给新版卡，之后两份独立成长。返回旧卡可能再次需要选择，不能仅凭角色名判断共享关系。

commit先应用内存，聊天先保存、Sidecar后保存。保存失败应保留错误提示及待保存内容，通过正常恢复入口重试；切回原聊天也需要核对目标版本。强制关闭后依据实际保存的聊天重算，不补造未保存的纯内存请求。作者网络副作用不由ERA撤销。

封存消息时的安全压缩整理普通操作和API记录，保留scope及重放结果；done函数不形成固定位置边界。压缩不是删除剧情或重新掷骰，也不是供作者手写era_tx的理由。购买的最终金币与食物应在压缩前后相同。

## 显示与辅助设置

| 设置                                 | 用途与冒险卡示例                                        |
| ------------------------------------ | ------------------------------------------------------- |
| 开启悬浮球                           | 显示管理入口；关闭不等于停用外置状态栏                  |
| 开启黑夜模式                         | 夜间阅读时切换ERA面板主题，不代替作者HTML样式           |
| 在AI消息尾部生成特殊符号、特殊符号值 | 传统状态栏占位入口；自定义模板时保持与局部正则一致      |
| 历史状态栏显示范围、超出范围行为     | 少量旧楼按需展示；购买前状态可单独展开                  |
| 单层模式、启用外置状态栏             | 推荐外置、按需单层；详见[显示模式](显示模式与状态栏.md) |
| 繁体转简体                           | 统一输入规范化；不要把中文变量的不同字形混作同一路径    |
| 调试模式                             | 开发排错时查看诊断；提供复现步骤和具体消息，勿分享密钥  |

技术指令、记录和阶段报告由ERA处理显示及后续提示投影，不需要重新添加旧隐藏正则。旧非托管模板、已经配置过的角色卡不会被初始化按钮自动迁移；直接按专题修改对应模板与设置。
