# 多阶段生成

战斗规则需要先确定检定结果再描写故事时，开启正文前规划；希望独立整理变量时，再开启正文后变量解析。两项独立开关，可以都关、只开一项或同时开启；群聊不支持这套Agent流程。

每楼的规划、正文生成记录和变量解析报告显示在正文旁的 ERA 报告区。展开报告或重新解析变量时，报告区独立更新。正文和状态栏继续由酒馆和酒馆助手呈现。

## 配置与发布

在ERA“多阶段生成”页配置每个阶段的尝试顺序、预设、模型及失败重试次数（0～16）。预设可选ERA内建、酒馆当前或指定已导入预设；重试超过尝试列表长度时复用最后一条。生成开始后的修改影响下一次生成。

当前预设包含未另存修改，保存到卡中时形成脱敏快照，不随本机同名预设后来改变。模型可以使用酒馆当前连接，或在尝试卡中选择/创建本机自定义API方案，加载模型后选择；加载失败不覆盖当前选择。空密码保留原密钥，清除或另存需要显式操作。

导出卡片携带阶段开关、尝试配置、预设快照和不透明方案引用；本机方案地址与密钥不随这份ERA配置分享。接收者需要重新绑定自定义方案，不会静默改用其他模型。这不表示整张卡不携带角色脚本：角色脚本由酒馆助手自身的随卡导出机制处理。

## 一场战斗的执行顺序

| 阶段 | 输出和顺序                                                                                             | RPG结果                                |
| ---- | ------------------------------------------------------------------------------------------------------ | -------------------------------------- |
| 规划 | JSON前标签/函数 → 原有JSON calls → JSON后标签/函数；JSON结构沿用当前内建规划预设                       | 骰点与检定先确定，正文读取完成后的状态 |
| 正文 | 使用玩家故事预设；普通变量标签和EraFCall按位置执行，后续结算读取正文执行后的状态，只补充尚需变更的部分 | 描写命中过程，调用作者指定业务         |
| 结算 | 直接输出Variable/Function六类标签和EraFCall，按原文顺序执行；没有变化输出空文本                        | 扣血、增加战利品，记录结果             |

例如结算输出：

```xml
<VariableEdit>{"era_demo":{"player":{"hp":{"$expr":"max(0, era_demo.player.hp - 3)"}}}}</VariableEdit>
<EraFCall name="era_rpg_buyFood" args='{"quantity":1}'/>
```

扣血先发生，购买再读取该位置状态。结算不输出operations JSON或代码围栏；报告中JSON字符串、引用和说明文本内的调用示例不作为执行指令。规划的JSON calls用于表达式函数，不等同于注册JavaScript工具的EraFCall。

## 纠错与重新生成

规划、结算候选的可纠错错误会撤销整次候选的变量、函数库、日志、scope、随机偏移、记录、done和结果，然后请求完整修正版。更早完成的阶段保留；成功commit也可能随所在候选回退。外部副作用不会回滚。

普通作者函数自身抛错保留成功前缀、标done并继续；但候选随后整体失败时这些效果仍一起撤销。网络/保存故障、目标失效和取消不应被误解成模型格式错误。纠错提示携带最近一次需修正回复及诊断，不要求模型给补丁；失败耗尽时保留候选起点，结算显示未结算。

| 操作                        | 保留与替换                                                     | RPG用途                      |
| --------------------------- | -------------------------------------------------------------- | ---------------------------- |
| 重新规划并继续              | 替换本轮规划及后续阶段                                         | 重新决定战斗检定             |
| 重新正文                    | 保留规划，替换正文及后续                                       | 保持检定，重写描写           |
| 重新结算                    | 请求模型前撤销旧结算，保留规划和正文；失败不恢复旧结算冒充成功 | 修正战利品结算               |
| Regenerate、Continue、Swipe | 按实际被替换/保留的历史恢复；Continue保留既有内容              | 重写回复、续写或探索另一分支 |

## 阶段订阅与报告

`ERA.generation.subscribe(listener,{stages:['planning','story','settlement']})`只通知成功完成的阶段，返回注销函数。事件有stage、result、executionId、completionId、trigger、chatKey及signal；有真实楼层时才提供messageId/mk/swipeId。

planning结果含plan和functionResults；story含story；settlement事件的operations是内部结构化结果，这不改变模型必须输出标签的规则。不要修改只读result试图替换模型输出。

监听器按注册顺序等待；异步回调可以暂缓后续流程，没有超时自动放行。可用于“规划完成后更新作者的战斗面板”，但应检查signal并在卸载时注销。监听器抛错会诊断后继续，已提交内容不因回调自身抛错自动撤销。候选整体回退仍以候选边界为准；楼内订阅者原有API目标绑定不会因此变成全局。

报告查看器可展开阶段结果、实际提示词、响应与诊断，并使用相应重生成按钮。完整过程只保存在有界页面记录中；页面关闭或记录被淘汰后，旧消息仍保留最终成果，不补造完整过程。查看报告不会重新执行函数。
