# 初级使用：快速制作一张冒险卡

你不必从零编写变量系统。先让 ERA 创建示例资源，再把示例状态栏、本文和需求交给 AI，让它修改成你的角色卡。

## 1. 安装并选定角色卡

在酒馆助手中导入并启用当前 ERA 脚本，打开一张准备制作的单角色卡，确认 ERA 悬浮球出现。源码开发者的构建方式见[开发总览](../developer/开发总览.md)；制卡时使用已构建的 ERA 脚本即可。

快速初始化是首次配置入口，两个按钮共用初始化标记；已经初始化的卡不能靠重复点击覆盖内容，应直接编辑已有资源。

## 2. 推荐：创建外置状态栏

打开 ERA 快速操作，点击“快速初始化-外置状态栏”。ERA 会保留原开场白，追加示例变量，并准备世界书规则、变量意图说明和外置状态栏。外置栏位于聊天与输入框之间，始终展示当前状态。

建议在 ERA 设置中按需勾选“单层模式”，然后点击“保存修改”。这会只显示最后一条 AI 回复，适合长篇冒险。它不是外置状态栏的必需条件，也不会随初始化自动开启。历史仍保留；需要查看或编辑旧消息时，关闭单层模式即可恢复酒馆正常显示窗口。旧楼界面的临时输入会随卸载丢失。

在外置区域点击“编辑”，复制完整 HTML 交给 AI。编辑器会自动保存；改完确认“已保存”，再点击“刷新”查看新模板。

## 3. 告诉 AI 你想制作什么

可以直接使用以下需求，并附上示例 HTML 与本文：

> 请把这张卡改成遗迹冒险 RPG。显示生命、金币、食物和背包。初始生命20、金币10、食物1，背包有火把。受伤扣血，奖励增加金币，休息消耗食物。请沿用外置状态栏环境，分别给出开场白中的变量初值、世界书“ERA变量意图说明”和完整状态栏HTML，并说明每项替换位置。三份内容使用相同变量路径，保留初始化标记，不重复追加初始化段落。

将开场白中示例变量段替换为与你的设定对应的内容，例如：

```xml
<VariableInsert>
{"era_demo":{"player":{"name":"阿斯特","hp":20,"max_hp":20,"inventory":["火把"]},"rpg":{"gold":10,"food":1}}}
</VariableInsert>
```

这里的数值只是开局状态。随后在角色主世界书的“ERA变量意图说明”中解释：`hp` 是当前生命，`gold` 是金币，`food` 是食物数量，`inventory` 是背包物品。让 AI 按剧情维护它们，而不是每条回复重新写初值。

普通变更使用三个标签：

| 意图               | RPG例子                 | 写法                                                                 |
| ------------------ | ----------------------- | -------------------------------------------------------------------- |
| 新增尚不存在的数据 | 获得遗迹任务            | `<VariableInsert>{"era_demo":{"quest":"探索遗迹"}}</VariableInsert>` |
| 修改已有数据       | 受到3点伤害，生命变为17 | `<VariableEdit>{"era_demo":{"player":{"hp":17}}}</VariableEdit>`     |
| 删除已有数据       | 移除临时任务字段        | `<VariableDelete>{"era_demo":{"quest":{}}}</VariableDelete>`         |

标签内写合法 JSON：属性名使用双引号，不加注释和多余逗号。没有变化时无需输出操作；新增用 Insert，修改用 Edit。把标签放在 AI 回复需要发生变化的位置，状态栏负责显示结果。

## 4. 放回内容并试聊

把生成的变量段放回开场白，意图说明放回世界书，HTML 放回外置编辑器。路径必须一致：生命变量是 `era_demo.player.hp` 时，状态栏也应读取该路径。

在新聊天中依次试验“受伤3点”“获得5金币”“休息消耗1份食物”：应分别看到生命17、金币15、食物0。修改初值后用新聊天验证，避免已有历史覆盖你刚改的开局设定。

确认界面显示与剧情一致后，保存并导出角色卡。外置 HTML 和相关开关随卡保存；外部资源链接不等于资源文件已经打包。发布前确认编辑器没有待保存提示。

## 另一条路线：传统楼内状态栏

如果希望每条剧情下都有一份对应状态栏，首次配置时选择“快速初始化-传统状态栏”。ERA 会创建楼内占位符及“ERA 状态栏模板”局部正则；从这个正则中复制并替换 HTML，而不是使用外置编辑器。开场白和后续回复中的占位符用于显示状态栏，应保留。

两条路线的变量设计和试聊方法相同，区别是状态栏放在哪里、读取哪一时刻的状态。传统模板的挂载结构应保留，详细调整见[显示模式与状态栏](advanced/显示模式与状态栏.md)。更多需求可从[作者指南](README.md)按主题查找。
